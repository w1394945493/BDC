
1. _get_stream() 的参数从整数编号变为 torch.device
   报错：
   AttributeError: 'int' object has no attribute 'type'
   原因：MMCV 传入 GPU 编号 0，但当前 PyTorch 的 _get_stream() 会读取 device.type，要求传入 torch.device。
   修改文件：
   [mmcv/parallel/_functions.py](/home/wangyushen/forks/GaussianOcc3D/mmlab/mmcv/mmcv/parallel/_functions.py)

<!-- # 原代码：传入整数 GPU 编号。
# streams = [_get_stream(device) for device in target_gpus]

# PyTorch 2.1 要求 torch.device；这里使用进程内的逻辑 GPU 编号。 -->

streams = [
    _get_stream(torch.device('cuda', device))
    for device in target_gpus
]
仅转换 _get_stream() 的参数，不要把整个 target_gpus 列表都改掉，其他 MMCV 代码仍使用整数编号，包括 CPU 哨兵 -1。
2. DDP 的旧私有属性已被移除
报错：
AttributeError: 'MMDistributedDataParallel' object has no attribute
'_use_replicated_tensor_module'
原因：MMCV 的 _run_ddp_forward() 依赖旧版 PyTorch 私有属性。训练可能走 train_step() 而正常运行，但评估调用 model(...) 时进入这条路径，触发错误。
修改文件：
[mmcv/parallel/distributed.py](/home/wangyushen/forks/GaussianOcc3D/mmlab/mmcv/mmcv/parallel/distributed.py)
在 _run_ddp_forward() 中，保留原函数说明，将原来的模块选择和调用代码替换为：

<!-- # 原实现依赖已移除的私有属性。
# module_to_run = self._replicated_tensor_module if \
#     self._use_replicated_tensor_module else self.module -->

<!-- # 保留 MMCV 对 DataContainer 的展开和当前设备搬运。 -->

if self.device_ids:
    scattered_inputs, scattered_kwargs = self.to_kwargs(
        inputs, kwargs, self.device_ids[0])
    inputs, kwargs = scattered_inputs[0], scattered_kwargs[0]

<!-- # 委托当前 PyTorch 原生实现，保留其 DDP 前向上下文管理。 -->

return super()._run_ddp_forward(*inputs, **kwargs)
不要只补一个 _use_replicated_tensor_module=False 属性来掩盖错误；上述方式让实际前向逻辑交由当前 PyTorch 管理。
这两处已在你的本地源码中修复。第一处通过 GPU 数据搬运测试，第二处通过双进程 CPU/Gloo 测试；它们解决的是已遇到的具体问题，不代表 MMCV 1.7.0 与所有 PyTorch 2.x 版本完全兼容。
